# 茶茶日历 1.10.1

面向安卓 8.0（接口级别 26）及以上设备的离线优先日历。首版重点解决“纪念日只有临近时才出现”的问题。

应用包名：`com.liangledecha.chachacalendar`

## 已实现

- 自动适配状态栏、刘海/打孔区域和底部导航栏安全区。
- 上下拖动月历区域，在单周、常规整月、全屏标签月历三种状态间流畅切换。
- 月视图左右滑动切换上/下个月；年视图左右滑动切换上/下一年，并带位移、淡入淡出动画。
- “年”提供 iPhone 风格的 12 个月缩略总览，点击任意月份进入对应月；“日程”列出全部事项。
- 点击年月标题打开年份、月份双滚轮，可直接跳转。
- 底部提供“今 / 日历 / 日程 / 待办 / ＋”，顶部只保留年、月视图。
- 支持纪念日、生日、待办和倒数日；重复规则包括每年、每月、每周、每日和不重复。
- 每条事项可独立选择公历或农历；农历事项保存农历月、日和闰月信息，年度重复时按真实农历日期换算下一次公历落点。
- 农历日期选择器的月份和日号使用“正月、腊月、初一、廿九”等中文，年份滚轮保持数字年份。
- 修正安卓天文农历在临界朔日的偏差；2027 年正月初六现在正确对应 2027 年 2 月 11 日，并有双向自动测试保护。
- 闰月完全按农历年份自动识别：有闰月时月份滚轮自动插入“闰×月”，没有闰月时不显示，不再提供手动开关。
- 月历可在设置中开关农历日号；农历事项在主界面下半区和桌面小组件中均显示农历日期。
- 设置中可分别开关传统节日、法定放假补班和二十四节气；同一天有多种信息时优先显示法定安排。
- 传统节日和二十四节气完全离线计算；法定节假日按年份联网更新并缓存七天，失败时继续使用已有缓存，2026 年另有国务院通知的内置兜底。
- 待办提供二十四小时制的分钟精度时间；其他三种类型保持全天事项。
- 待办页左侧提供完成选择框：完成后整行变灰并从月历、日程和小组件隐藏，取消完成即可恢复。
- 未办结待办超过设定日期和分钟后以红色标注“已过期”，今天的列表和小组件会持续保留；已办结待办到期后进入待办页会询问保留或删除。
- 待办页支持点击整行编辑、长按整行删除；选择框不抢占列表焦点，可正常勾选和取消。
- 选中任意日期后，下半区以该日期为基准严格执行提前显示窗口；例如“15天前显示”只展示之后 0–15 天内的事项。
- 选中非今天日期后，摘要显示“2天后 8月28日”或“2天前 8月24日”；从月视图新建事项时自动使用该选中日期，仍可手动修改。
- 全屏月历在日期格内显示纪念日、生日和待办标签。
- 全屏月历中的过长事项名称左对齐停一秒后向左滚动，右边界对齐后再停一秒；短名称保持静止。
- 每条日程可独立选择：一直显示（默认）、15、7、5、3 天前显示。
- 下半区按下一次发生日期排序，持续显示倒计时；点击编辑，长按删除。
- 最左侧 ISO 年周数显示，可在设置中关闭。
- 桌面小组件包含系统驱动的实时钟、日期、天气入口和当前应显示的事项；默认尺寸显示四条，纵向放大后按实际可用高度逐行增加，内容从顶部紧凑排列。
- 小组件顶部时间日期、下方事项文字可分别选择五级字号；一级保持原默认大小，五级适合大面积或全屏小组件。
- 小组件背景提供不透明、透明 15%、30%、45%、60% 五档选择，不增加后台刷新频率。
- 自动探测主流厂商系统天气应用，天气区域可直达系统天气。
- 经用户授权后，把新增、编辑和删除同步到可写系统日历，并写入发生时提醒。

## 架构与功耗

- `EventStore`：SQLite 单一数据源，不需要联网。
- `LunarDateUtils`：使用离线中国民用农历算法完成双向换算和闰月识别，结果与系统民用历书保持一致。
- `CalendarCultureUtils`：离线计算传统节日、常用节日和二十四节气。
- `HolidayRepository`：仅发送查询年份，按年下载并缓存法定放假和补班数据，不上传任何用户事项。
- `MonthCalendarView`：原生 Canvas 绘制三态月历，避免复杂 UI 框架常驻开销。
- `MainActivity`：编辑、筛选和视图状态协调。
- `CalendarWidgetProvider`：只在日期、时区或本地数据变化时刷新；时间由系统 `TextClock` 更新，不运行分钟级定时任务。
- `SystemCalendarSync`：把事项、重复规则和提醒写入安卓标准日历提供程序；通知由系统日历应用执行。
- `SystemWeatherBridge`：厂商无关的适配边界。目前只调用公开的应用启动入口，不读取私有数据库。

Android 没有统一的公开 API 允许第三方应用读取“系统天气”的温度和预报，各厂商也通常不开放私有天气数据库。为保持跨品牌兼容和零高危权限，首版不会使用 root、无障碍或通知监听。后续可在 `SystemWeatherBridge` 内增加获得厂商正式授权的数据适配器，而不影响日历核心。

## 本地构建

需要 JDK 17 和 Android SDK 35：

```text
gradle assembleDebug
```

项目仅使用一个 MIT 许可的离线农历运行时依赖，许可说明见 `THIRD_PARTY_NOTICES.md`，不申请定位权限。网络权限只用于按年更新法定节假日；系统日历同步需要用户授予“读取日历”和“写入日历”权限，拒绝权限不会影响本地功能。
